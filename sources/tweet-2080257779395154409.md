## Zusammenfassung

Robert C. Martin schreibt, er programmiere seit den späten 1960ern und lese den Code seiner Agenten inzwischen nicht mehr, um ihre Produktivität nutzen zu können. Stattdessen umgebe er sie mit strengen Vorgaben: Unit-Tests, Gherkin-Tests, QA-Prozeduren, Qualitätsmetriken, Mutation Testing, Testabdeckung und weitere. Sein Vertrauen in den Code begründet er damit, dass der Code alle diese Prüfungen bestehen muss. Der Post enthält keine Beispiele, Projektdaten oder Fehlerquoten.
