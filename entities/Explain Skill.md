# Explain Skill

## Format ladder (Stand 2026-10)

The [Explain Skill](https://github.com/ARYANK-08/agentic-dev-kit/blob/main/skills/explain/SKILL.md) starts with relaxed [Simplified Technical English](Simplified%20Technical%20English.md) text, moves to diagrams for flows/relationships and HTML sheets for large overviews, and creates videos only on request. It avoids expanding a small question into a larger artifact. [tweet-2105842218418544773](../sources/tweet-2105842218418544773.md)

HTML sheets use bordered, lettered panels with real examples; flows use a minimal hand-drawn diagram style. The instructions distinguish the two layouts and include terminal ASCII fallbacks. [tweet-2105842218418544773](../sources/tweet-2105842218418544773.md)

## Writing and grounding (Stand 2026-10)

Rules limit procedural sentences to 20 words, descriptive sentences to 25 words and paragraphs to six sentences; use active voice, common words and consistent terminology. Start with the answer, then mechanism and a concrete example. [tweet-2105842218418544773](../sources/tweet-2105842218418544773.md)

Code explanations must use the actual repository and file/line references. ELI13 mode uses one consistent everyday analogy, introduces necessary terms in plain words and avoids talking down to the reader. [tweet-2105842218418544773](../sources/tweet-2105842218418544773.md)

## Dependencies and relation (Stand 2026-10)

The complete saved skill refers to Artifact tools and separate diagramming/design/video skills; availability depends on the host, and successful portability was not tested. [tweet-2105842218418544773](../sources/tweet-2105842218418544773.md)

Unlike [Answer Me With HTML](Answer%20Me%20With%20HTML.md), this is a format/style instruction template rather than a bundled renderer; both apply [HTML as LLM Output](../concepts/HTML%20as%20LLM%20Output.md). [tweet-2105842218418544773](../sources/tweet-2105842218418544773.md)
