# Nango

## Drei Bausteine (Stand 2026-09)

[Repository](https://github.com/NangoHQ/nango): Auth verwaltet OAuth, API-Schlüssel und Token-Refresh; Proxy führt authentifizierte Anfragen samt Retry-/Rate-Limit-Behandlung aus; Functions führen TypeScript-Integrationslogik mit Runtime, Speicher und Beobachtbarkeit aus. [tweet-2098941338297458746](../sources/tweet-2098941338297458746.md)

Die README nennt Agent-Tool-Calling/MCP, Datensynchronisation, Webhooks, API-Vereinheitlichung und kundenspezifische Konfiguration. nango.openConnectUI bindet die Autorisierung in ein Frontend ein. [tweet-2098941338297458746](../sources/tweet-2098941338297458746.md)

## Grenzen und Editionen (Stand 2026-09)

Die behauptete Unterstützung von über 900 APIs und Skalierungs-/Compliance-Angaben sind Herstellerdarstellung. API-Zugang und Autorisierung bleiben Voraussetzungen; die Plattform ersetzt keine Berechtigungsentscheidung. [tweet-2098941338297458746](../sources/tweet-2098941338297458746.md)

Die gespeicherte README nennt Elastic License, kostenpflichtige Cloud-/Enterprise-Versionen und kostenloses Self-Hosting mit begrenztem Funktionsumfang. Daher ist die pauschale kostenlose SaaS-Ersatzbehauptung des Sammelposts zu weitgehend. [tweet-2098941338297458746](../sources/tweet-2098941338297458746.md)
